## 2. 从什么课程知识点出发？

本作业选取的课程切入点是 **Workflow 与 Agent 的任务控制分工**，并联系“AI 智能体也是分布式系统”中工具执行、超时、重试与状态一致性的知识。

Workflow 可以包含状态机、条件分支、传感器反馈与故障恢复；它并不是只会执行固定动作。Agent 则将一部分高层工具选择交给模型在运行时完成。两者的区别不等于“有没有智能”，更不意味着 Agent 必然更可靠。相关概念及技术先例见[参考文献](docs/references.md)。

最初想法是“正常执行 Workflow，异常时调用 Agent”。随后通过质疑和查阅文献发现，这种混合架构已有研究，不能直接作为原创贡献。本作业因此将范围缩小为：

> **水下机械臂已经完成持物下降，但系统仍无法确认物体稳定支撑时，是否值得把后续诊断交给 Agent？**

## 3. 为什么只研究这个节点？

正常流程为：

```text
目标感知 → 抓取 → 抬升 → 搬运 → 持物下降 → 支撑确认 → 释放 → 撤回
                                              ↑
                                    本研究只处理 UNKNOWN
```

统一研究入口：下降动作报告完成、夹爪仍闭合、在线支撑验证结果为 `UNKNOWN`。

下降完成、发生接触、载荷转移、稳定支撑是不同条件。工具执行成功，也不代表物理放置成功。如果视觉与接触反馈结论不同，应先判断是否采集于同一动作之后、是否过期、是否描述同一个物理命题，而不是立即调用大模型。

本作业第一阶段研究**诊断与选择性接管**，不重新开发抓取规划、运动控制、力控或大模型。第二阶段只有接入经验证的受限恢复技能并真正执行释放和撤回，才评价完整放置成功率。

## 4. 拟研究的方法

完整流程：

```text
SUPPORT_UNKNOWN
  → 读取带时间戳、动作 ID 和版本的状态
  → 检查证据质量、时效性、可比性与物理语义
  → Workflow 处理明确的低成本数据/诊断问题
  → 比较继续 Workflow 与调用 Agent 的预期收益和成本
  → 选择 Workflow / Agent / 安全处置
  → 独立安全审核
  → 执行已注册技能
  → 独立验证支撑状态并记录结果
```

### 两个版本

**D0 / V0：启发式基线。** 使用证据有效性、历史诊断进展、可用工具及预算作保守接管；本质仍是规则策略，不宣称算法首创。

**D1 / V1：待验证的收益预测方案。** 在同一可重置异常状态上分别运行 Workflow 和 Agent，学习两种后续诊断策略的条件收益差异。

```text
Agent 净增量收益
= 正确诊断概率的预计增量
- 时间权重 × 预计额外总耗时
- 资源权重 × 预计额外计算成本
```

成功率、时间与资源的换算权重在开发集固定。安全规则是独立约束，不能用提高成功率抵消危险释放。第一版 D1 在固定检查点作一次接管选择，选定策略后执行剩余诊断，避免将一次转交标签错误用于多轮路由。

本作业的候选技术增量是：**是否能用状态证据与诊断历史预测 Agent 相对强规则 Workflow 的实际增量价值**。成本敏感决策和选择性求助本身已有先例，因此目前不声称提出全新理论。

## 5. Agent 有哪些权限？

Agent 可以申请重新观测、检查物体姿态、重检接触/载荷状态，或请求安全终止。是否执行由独立执行器和安全监督器决定。

| 模块 | 职责 |
|---|---|
| Workflow | 正常任务、明确规则诊断与后续流程 |
| 接管决策器 | 判断是否值得调用 Agent |
| Agent | 从白名单中选择高层诊断技能 |
| 工具执行器 | 参数、权限、请求去重与执行状态管理 |
| 安全监督器 | 前置条件审核、运动中保护、动作否决 |
| 独立支撑验证器 | 根据合法观测判断支撑状态，不采纳语言判断作为真值 |

**不开放给 Agent：** 直接关节/速度/力矩命令、直接张爪、修改安全阈值、绕过安全检查。

所有 Workflow 动作同样经过安全监督。超时不等于动作未执行；发生执行状态不明时先查询原请求，不重复提交物理动作。

## 6. 四组对照实验

| 组别 | 策略 | 主要问题 |
|---|---|---|
| A | 强规则 Workflow，不调用 Agent | 不使用大模型是否已经足够？ |
| B | UNKNOWN 后立即调用 Agent | 无条件接管的能力和成本如何？ |
| C | 相同 Workflow 固定 N 次尝试后接管 | 简单阈值是否足够？ |
| D | 状态证据 + 相对收益/成本选择性接管 | 是否改善效果—成本权衡？ |

D0 和 D1 是 D 的两个实施阶段，结果不能混写。四组共享观测、工具、验证器、安全限制与总预算；B/C/D 使用同一个 Agent 模型、提示词和推理设置。不得削弱 A 的工具或信息。

## 7. 分级异常与泛化

S1 短暂传感器误报；S2 物体尚有间隙；S3 姿态偏移或局部接触；S4 可比的多源证据冲突；S5 复合异常；S6 无已验证安全继续路径。

所有场景均从同一个 `SUPPORT_UNKNOWN` 入口开始，并通过扰动参数和独立的物理、视觉、接触、Agent 随机种子控制。扰动更大不必然更难，等级需依据预实验标定。入口即需安全保护的情况单列压力测试，不归功于接管算法。

分别评价新随机种子、未见扰动强度和未见异常组合；前者只代表同分布稳定性，不能被宣传成未知故障泛化。

## 8. 真值隔离与复现

仿真真实接触、物体精确状态、故障标签、难度、随机种子及离线虚拟释放结果只供场景生成器和离线评价器使用。Agent、Workflow、在线验证器与在线安全模块不得通过工具读取隐藏真值。

同一 Episode 及其策略分支属于同一训练/开发/测试划分。记录实际观测、模型输出、请求 ID、工具结果和总耗时；种子不能替代执行记录。数据采集前固定标签、成本、预算、终止条件和测试集。

## 9. 评价指标：防止“始终停止”获得虚假优势

核心指标包括正确诊断率 CDR、诊断覆盖率 DC、错误确认支撑率 FSR、限时正确诊断率 CDR(τ)、Agent 接管率、实际推理次数、工具次数、总耗时及安全违规。

始终停止的方法：`CDR=0`、`DC=0`；因没有作出判断，其已决策错误率为 `N/A`，不是 0%。只看零危险事件不能说明方法优秀。只有真正完成物理恢复、释放与撤回，才记录安全任务完成率。

优先级是：**共同安全边界 → 足够诊断/任务能力 → 比较真实时间与计算成本**，不是任意把危险动作与成功率相抵消。

## 10. 消融与可证伪假设

消融包括：删除接管模型中的证据特征、删除诊断历史、去掉成本惩罚、以 D0 替代收益学习，以及“证据 × 成本”2×2 交叉实验。删掉预测器特征后重新训练；基本数据校验与安全监督始终保留，Agent 介入后的信息权限不变。

重点检验：证据是否改变收益预测；预测是否改变接管；改变后的决策是否带来实际收益。若 Full 最好但交互效应不显著，不能直接宣称两个模块协同。如果强规则或轻量模型更便宜且效果相当，应接受当前任务不需要复杂 Agent 的结论。
